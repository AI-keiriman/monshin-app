# 要件定義

## 1. 誰のために、何を

- 対象：ギターやベースを弾いている人。
- 課題：楽器が壊れても、修理に出すまで料金がわからない。そのため修理に出せず、弾かないまま置いているか、壊れたまま使っている。
- アプリがすること：持ち主が症状を入力すると、AI がいくつか質問をして、考えられる原因と料金の見積を出す。

## 2. 課題の要件（教材からの制約）

| 区分 | 要件 |
|---|---|
| 範囲 | コアは3機能まで。ログインを含めるなら2機能 |
| 外部サービス | 決済（Stripe）と AI 機能（Claude API）は、どちらか1つまで。このアプリは AI 機能を使う |
| 技術 | Python 3.14、Flask、Flask-SQLAlchemy（Mapped / mapped_column）、Flask-Migrate、uv、Pico CSS |
| DB | 開発とテストは SQLite。本番は MySQL 8.0（PyMySQL）。SQLite でしか動かない書き方をしない |
| 骨組み | marche-app と同じ構成。create_app、extensions.py、ProxyFix、.flaskenv、.env.example |
| テスト | メモリ上の SQLite。外部 API はフェイクに差し替える |
| 公開 | marche-app と同じサーバーに置く。gunicorn のポートは 8001。サービス名を変える。自動デプロイを入れる |
| 公開前 | security-audit を実行し、危険度「高」を直す |
| 発表 | 本番の URL でデモをする。デモは2分程度、機能は3つ以内 |
| 成果物 | docs/spec/requirements.md、docs/design/screens.md、docs/design/database.md、CLAUDE.md |

AI 機能を入れる場合の決まり（教材の5節）：

| 決まり | このアプリでの対応 |
|---|---|
| API を呼ぶ処理は services/ai.py の1か所だけ | そのとおりにする |
| テストではフェイクに差し替える | そのとおりにする |
| モデルは .env の ANTHROPIC_MODEL で変える。既定は claude-haiku-5-5 | そのとおりにする |
| max_tokens を小さめにする | 値は設計で決める |
| ログインした人だけが使える。1人あたりの回数に上限を付ける | ログインを作る。上限は下の F1 に書く |
| 本番用のキーを別に作る。Console の上限を確認する。自動チャージはオフ | 公開の日に行う |
| API が失敗しても画面が落ちない | 下の F1、F2 に書く |

## 3. 機能

### F0 ログイン（コアの数に含めない土台）

- 利用者は、メールアドレスとパスワードで登録できる。
- 利用者は、ログインとログアウトができる。
- 問診の画面は、ログインした人だけが開ける。
- 作りは marche-app（Flask-Login）を真似る。ロールは作らない。

### F1 問診

1. 利用者は、楽器の種類を選ぶ（アコースティックギター、エレキギター、ベース）。
2. 利用者は、症状を文で入力する（必須）。
3. 利用者は、写真を1枚付けられる（任意）。
   - 写真の欄の下に、「音声・動画を追加（任意）」の欄を出す。ファイルは選べるが、アプリは受け取らない（欄だけ）。
4. 利用者が送ると、AI が追加の質問を3問返す。
5. 利用者は、質問に文で答えて送る。

決まり：

- AI を呼ぶ回数は、1回の問診につき2回にする（質問を作る、結果を作る）。会話を何往復もさせない。費用と時間の上限を決めるためである。
- 写真は AI に渡す。
- 1人が1日に始められる問診は5回まで。超えたら、その旨を画面に出す。
- AI が失敗したら、入力した内容を残したまま「今は AI を使えません」と出す。画面は落とさない。

### F2 診断の結果

1. アプリは、考えられる原因を最大3つ出す。それぞれに短い説明を付ける。
2. アプリは、料金の見積を出す。出し方は、料金表の中身で決まる。
   - 下限と上限がある分類：「◯円〜◯円」
   - 下限だけがある分類：「◯円〜」
   - 金額が無い分類：「要見積」
3. アプリは、3つの出口のボタンを並べる（修理依頼に進む、ホームに戻る、買取査定をする）。
4. 利用者が出口を1つ選ぶと、アプリはその選択を保存する。
5. 利用者は、自分の過去の問診の一覧と結果を見られる。

決まり：

- 料金の金額は、AI に作らせない。AI は「症状の分類」を選ぶだけにする。金額は、アプリが持つ料金表から引く。理由：AI が根拠のない金額を出すことを防ぐ。テストで結果が毎回同じになる。
- 「買取査定をする」を選んだときは、「買取査定」の枠を出す。金額、査定、申し込みは作らない。
- 「修理依頼に進む」を選んだときは、「修理の依頼」の枠を出す。依頼の受け付けと送信は作らない。
- 「ホームに戻る」を選んだときは、選択（そのまま使う）を保存して、トップへ移る。

## 4. やらないこと

- 工房の側の画面（問診票の一覧、返信、見積）。
- 買い取りの査定と申し込み（「買取査定」の枠だけ出す）。
- 修理の予約、決済、メールの送信。
- 音声・動画の受け取り、保存、AI による読み取り（「音声・動画」の欄だけ出す。ファイルは受け取らない）。
- AI との自由な会話（何往復もするチャット）。
- パスワードの再設定、退会、プロフィールの編集。
- 管理者の画面とロール。
- スマホ向けの作り込み（Pico CSS の標準のままにする）。

発表では、上の項目を「今後の展望」として話す。

## 5. 画面（詳細は docs/design/screens.md に書く）

| 画面 | 誰が開けるか | 内容 |

## 6. データ（詳細は docs/design/database.md に書く）

| データ | 主な中身 |
|---|---|
| 利用者 | メールアドレス、パスワードのハッシュ |
| 問診 | 利用者、楽器の種類、症状の文、写真の置き場所、状態、選んだ出口、作成日時 |
| 質問と答え | 問診、質問の文、答えの文、順番 |
| 原因の候補 | 問診、原因の名前、説明、順番 |
| 料金表 | 症状の分類、下限の金額（空でもよい）、上限の金額（空でもよい） |

アップロードしたファイルは、Git に入れない（.gitignore に足す）。

## 7. 確かめること（テストの種）

- ログインしていない人が問診の画面を開くと、ログインの画面に移る。
- 症状の文が空のときは、送れない。
- 問診を送ると、フェイクの AI が返した3問が画面に出る。
- 答えを送ると、原因の候補と料金の見積が出る。金額は料金表の値と同じである。
- 料金表に金額が無い分類では、「要見積」と出る。
- 音声・動画の欄で選んだファイルは、サーバーに送られない。ファイルを無理に送っても、アプリは保存しない。
- メーカー、機種名、使用年数は、空のままでも問診を始められる。入れたときは、AI に症状と一緒に渡る。
- 「買取査定をする」を選ぶと、「買取査定」の枠が出る。金額は出ない。
- 「ホームに戻る」を選ぶと、トップへ移る。
- 出口を選ぶと、選択が保存される。
- 他人の問診の URL を開くと、見られない。
- 写真は、公開のフォルダーに置かない。ログインしていない人が写真の URL を開くと、ログインの画面に移る。
- 他人の問診の写真の URL を開くと、見られない。
- 1日の上限を超えると、問診を始められない。
- AI が失敗しても、画面が落ちない。
- 許可していない種類や大きさのファイルは、受け付けない。

## 8. デモの筋書き（2分）

聞き取りの3人目の事例を使う。

1. デモ用のアカウントでログインする。
2. 楽器に「ベース」を選び、症状に「トーンノブが効かない」と入れる。写真を付ける。
3. AI の3つの質問に答える。
4. 結果の画面で、原因の候補と料金の見積を見せる。
5. 「直す」を選ぶ。一覧に記録が残ることを見せる。

前日までに、本番の URL でこの操作を1回通す。動いている画面のスクリーンショットも用意する。

## 9. 企画発表から変えたこと（最終プレゼンの項目4で話す）

| 変えたこと | 理由 |
|---|---|
| 「問診票を工房に届ける」機能を削った | 範囲を絞るため |
| ログインを足した | AI 機能は、ログインした人だけが使える決まりのため |
| AI との対話を、3問を1回で聞く形にした | 費用と時間の上限を決めるため |
| 音声の入力は、欄だけにした | 範囲を絞るため。AI が音声を読めるかも未確認だった |
| 音声の欄を「音声・動画」にし、「準備中」の表示を消した（2026-11-19） | 完成したときの画面の形を見せるため。ファイルは、まだ受け取らない |
| 楽器の情報（メーカー、機種名、使用年数）の欄を足した（2026-11-19） | AI が原因を絞る手がかりにするため。どれも任意 |
| 買い取りの提案は、枠だけにした | 範囲を絞るため |
| 料金表の分類を4つから12に増やした（2026-11-19） | 診断の手引きで原因を絞れても、分類が無いと「要見積」しか出せないため |
| 「診断の手引き」の表を足した（2026-11-19） | 症状ごとの確かめる点と見分け方を、工房の職人が直せる形で持つため。AI は、近い行があれば、それに沿って質問と診断を作る |
| 出口のボタンの名前を「修理依頼に進む」「ホームに戻る」「買取査定をする」に変えた（2026-11-19） | 押した後に何が起きるかが、名前で分かるようにするため |
| 名前を「ギター問診室」から「ギター修理の AI 見積」に変えた | 名前だけで、何のアプリかが伝わるようにするため |

## 12. 料金表（デモ用）

- よくある症状に当たる分類を入れる。すべての修理を網羅しない。
- 金額は工賃の目安で、デモ用である。実際の金額は、工房が決め直す。
- 表示の3通り（◯円〜◯円、◯円〜、要見積）が、それぞれ1つ以上出るようにした。

| 分類（AI が選ぶ） | 症状の例 | 下限 | 上限 |
|---|---|---|---|
| ポットの不良 | ノブが効かない。回すと雑音が出る | 3,000円 | なし |
| フレットの消耗 | 音が詰まる。フレットがへこんでいる | 16,000円 | 90,000円 |
| ネックの折れ、ひび | ヘッドやネックが割れた | 65,000円 | なし |
| ジャック（ケーブルの差し込み口）の不良 | ケーブルを動かすと音が途切れる。差し込み口がぐらつく | 1,800円 | 4,500円 |
| 切り替えスイッチの不良 | 一部の位置だけ音が出ない。切り替えると雑音が出る | 2,500円 | 6,500円 |
| アース・配線の不良 | ジーという雑音がずっと出る。弦に触れても変わらない | 2,800円 | 17,000円 |
| ネックの反り・弦の高さの調整 | 全体的にビビる。弦が高くて押さえにくい | 1,800円 | 8,500円 |
| ナット（弦を支える溝の部品）の不良 | 開放弦だけビビる。合わせるときにキンと鳴って、音が狂う | 1,700円 | 13,000円 |
| ペグ（糸巻き）の不良 | 糸巻きがガタつく、空回りする | 1,200円 | 5,500円 |
| ブリッジのはがれ（アコースティック） | ブリッジの後ろにすき間がある。浮いている | 5,500円 | 32,000円 |
| ボディの割れ・膨らみ（アコースティック） | 表の板が割れた、膨らんでいる | 2,500円 | 32,000円 |
| その他、判断できない | 上のどれにも当たらない | なし | なし |

聞き取りの3人の事例は、次の分類に当たる。

| 事例 | 分類 | 出る表示 |
|---|---|---|
| 1人目：アコースティックギターのネックにひび | ネックの折れ、ひび | 65,000円〜 |
| 2人目：エレキギターのフレットの消耗 | フレットの消耗 | 16,000円〜90,000円 |
| 3人目：ベースのトーンノブが効かない | ポットの不良 | 3,000円〜 |

楽器の種類で金額を変える決まりは作らない。分類を増やすときは、この表に行を足すだけでよい。
